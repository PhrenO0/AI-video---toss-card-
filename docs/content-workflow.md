## 1. 기획 원칙

### 1-1. 조회수가 아니라 체류시간

Ref 01의 핵심 주장이자 우리 1주차 실패와 정확히 맞물리는 지점.

> "첫 장만 클릭하게 만드는 것과 끝까지 읽게 만드는 것은 전혀 다른 이야기입니다.
> 조회수만 높은 콘텐츠와 저장·공유까지 이어지는 콘텐츠의 차이는 기획에서 시작됩니다."

1주차 실적은 조회 171 · 좋아요 3 · 전환 0이었다. 도달이 낮았던 것은 해시태그 부재 탓이지만,
**도달이 회복돼도 체류·저장 설계가 없으면 숫자만 커지고 전환은 그대로 0**이다.

- X: 리포스트 ×20 / 리플 ×13.5 / 북마크 ×10 / 좋아요 ×1 → 좋아요는 사실상 무의미
- Instagram: 하우투 장르 저장률 18.3%로 최고 → 우리 콘텐츠는 전부 하우투로

### 1-2. 후킹 조건 (그대로 채택)

- 너무 자극적이지 않을 것
- 뉴스 헤드라인처럼 작성
- 저장하고 싶은 정보처럼 보일 것
- **클릭베이트 금지**

토스 홍보 가이드의 "첫 1~3초 안에 관광객의 상황이나 혜택이 보여야 한다"와 충돌 없음.
오히려 클릭베이트 금지 조항은 가이드의 "확인 없이 단정하는 콘텐츠 금지"와 같은 방향이다.

### 1-3. 저장률 3장치

콘텐츠 한 편마다 아래 셋을 **의도적으로 배치**한다.

| 장치 | 목적 | 우리 적용 예 |
|---|---|---|
| 저장하고 싶은 문장 | 북마크 (×10) | `保存しておくと当日あわてません` |
| 공유하고 싶은 문장 | 리포스트 (×20) | 숫자·비교가 든 한 줄 |
| 댓글이 달릴 질문 | 리플 (×13.5) | `どこで弾かれましたか？` |

기존 초안은 "마지막 질문"만 넣고 있었다. **3종 세트로 확장**한다.

## 2. 20페이지 구조 → 우리 포맷 압축 매핑

Ref 01의 20페이지 구성은 인스타 캐러셀 전용이라 그대로 쓸 수 없다.
X는 단일 포스트가 기본이고, 신규 계정이 20장짜리를 만들 여력도 없다.
**흐름은 유지하고 길이만 압축**한다.

### 2-1. X 단일 포스트 (6행)

| 원본 구간 | 우리 행 | 역할 |
|---|---|---|
| 1p 후킹 | 1행 | 훅 (+ 이모지 1개, 줄 끝) |
| 2p 왜 이 이야기 | — | 생략 (공간 없음) |
| 3~5p 공감 상황 | 2행 | 공감 |
| 6~10p 문제 원인 | 3행 | 원인 |
| 11~15p 사례·예시 | 4행 | 답 (제품은 여기 한 번만) |
| 16~18p 인사이트 | — | 생략 |
| 19p 핵심 요약 | 5행 | 보너스 (✨로 마감) |
| 20p CTA | 6행 | 질문 → 리플 유도 |

마지막에 해시태그 **3~4개** (카테고리 + 지역 + 지역 + 품목). X에서 태그를 많이 달면 저품질 신호다.

### 2-2. Instagram 캐러셀 (10장)

20장은 초기 계정에 과하다. 절반으로 압축하되 **연결 문장은 전 장에 유지**한다.

| 장 | 역할 |
|---|---|
| 1 | 후킹 |
| 2~3 | 공감 상황 |
| 4~5 | 문제 원인 |
| 6 | 답 |
| 7~8 | 실제 사례·사용 장면 |
| 9 | 핵심 요약 |
| 10 | CTA |

### 2-3. 연결 문장 (필수)

**모든 장 하단에 다음 장을 보게 만드는 한 줄을 넣는다.** Ref 01이 가장 강조하는 장치.

- ❌ `次のページへ` — 아무 정보가 없음
- ✅ `でも、ここで多くの人がつまずきます` — 다음 내용을 예고
- ✅ `理由は3つあります` — 개수를 예고

## 3. 발행 전 검수 체크리스트

Ref 01의 7개 항목과 토스 가이드의 6개 항목을 **하나로 병합**한 최종본.
발행 담당이 매번 확인한다.

### 기획
- [ ] 첫 장이 클릭하고 싶은가?
- [ ] 두 번째 장을 넘길 이유가 있는가?
- [ ] 중간에 이탈할 페이지가 있는가?
- [ ] 마지막까지 읽으면 얻어가는 정보가 있는가?
- [ ] 저장할 이유가 있는가? (저장 문장이 실제로 들어갔는가)
- [ ] 공유할 이유가 있는가?
- [ ] CTA가 자연스러운가? (억지스럽지 않은가)

### 정확성 — 토스 가이드
- [ ] 관광객에게 유용한 이유가 첫 부분에 드러나는가?
- [ ] 핵심 메시지가 **하나**로 명확한가?
- [ ] 금지 표현을 쓰지 않았는가? (§3-1)
- [ ] 명시한 조건이 최신 정보와 일치하는가?
- [ ] 다음에 무엇을 하면 되는지 알 수 있는가?
- [ ] **디스클레이머가 눈에 보이는 곳에 있는가?**

### 3-1. 절대 빼면 안 되는 4가지 표현

문장을 다듬다가 빠지는 순간 **금지 표현**이 된다.

| 필수 표현 | 빠지면 생기는 문제 |
|---|---|
| `プリペイドカード` (선불카드) 명시 | 신용·체크카드로 오인 |
| `最初の1枚` (첫 1장) 한정 | "모든 발급·재발급 항상 무료"가 되어 허위 |
| `カード払いができるお店` 조건 유지 | 현금만 받는 가게까지 포함되어 허위 |
| `T-money対応の` 한정 | "모든 교통수단 조건 없이"가 되어 허위 |

### 3-2. 일본인 타깃 최대 리스크 — 충전수단

토스 가이드의 해외간편결제 충전수단은 **홍콩·태국·말레이시아·필리핀·인도네시아**뿐이며
**일본 결제수단이 없다.** 계좌이체는 한국 계좌가 필요해 관광객에게 해당 없음.

→ 일본인의 현실적 충전 경로는 **편의점 현금 충전**이고, 이는 **원화 현금이 필요**하다는 뜻이다.

**`両替不要` / `両替所に行かなくていい` 류 소구는 절대 금지.**
경쟁 제품 WOWPASS는 키오스크에 엔화를 넣으면 원화로 충전되는 환전 겸용 구조다.
**환전 축에서 싸우면 진다.** 우리 축은 `무료 + 여권만 + 카드 한 장`.

## 4. 이미지 일관성 — reference 첨부 원칙

Ref 02의 핵심 발견:

> "왕 주의: 프롬프트만으로는 커스텀 캐릭터가 정확히 안 나옴. **캐릭터 이미지를 직접 첨부해야 함.**"
> "매 장마다 동일 reference 재사용 → 캐릭터 일관성 유지"

이 원칙은 이미 [`storyboard.md`](./storyboard.md)에서 캐릭터 시트·로케이션 마스터샷으로 실천 중이다.
**여기에 제품 애셋을 추가**한다.

### 4-1. 우리가 이미 가진 reference

`assets/toss-card/` 에 토스 선불카드 공식 애셋 10장이 있다.

| 파일 | 용도 |
|---|---|
| `pre-card-black-front/back.png` | 카드 실물 정면·후면 |
| `pre-card-white-front/back.png` | 화이트 버전 |
| `pre-card-hologram-front/back.png` | 홀로그램 버전 |
| `hand-pre-card-hologram.png` | 손에 든 컷 |
| `pre-card-bustag-holo-apng.png` | 버스 태그 장면 |
| `pre-card-wide-full.png` | 와이드 |

**AI로 이미지를 생성할 때 이 애셋을 reference로 반드시 첨부한다.**
첨부 없이 프롬프트만으로 만든 카드는 형태·로고가 실물과 달라져 허위 표시가 된다.

### 4-2. AI 생성 금지 영역

금융 서비스이므로 **"실제로 이렇게 작동한다"고 보이는 장면**은 생성 이미지로 만들지 않는다.

| 구분 | 판정 |
|---|---|
| 카드 실물 | ❌ 실촬영 또는 공식 애셋만 |
| 앱 화면 | ❌ 실캡처만 (개인정보 마스킹 필수) |
| 결제·개찰구 태그 순간 | ❌ 실촬영만 |
| 텍스트 카드 배경 | ✅ 생성 가능 |
| 아이콘·일러스트 | ✅ 생성 가능 |
| 분위기용 추상 배경 | ✅ 생성 가능 |
| 실제 서울 장소 사진 | ⚠️ 실촬영 권장 — 일본인 이용자는 서울 지리에 밝은 사람이 많음 |

## 5. 레이아웃 먼저, 텍스트 나중

Ref 03의 한 문장이 이번 채택에서 가장 실용적이다.

> "레이아웃 먼저 정하고, 텍스트 얹기.
> 이미지 먼저 만들고 글자를 얹으면 무조건 스티커 티가 난다.
> 프롬프트에 **'왼쪽 위 1/3은 헤드라인 자리로 비워줘'** 한 줄이면
> 이미지가 글자 자리를 만들며 태어난다."

### 5-1. 적용 규칙

- AI 이미지 생성 프롬프트에 **글자 자리를 먼저 지정**한다
  - 예: `leave the top-left third as empty negative space for a headline`
- 카드 디자인은 **1080×1080 그리드에 텍스트 블록을 먼저 배치**한 뒤 배경을 채운다
  ([`design-system.md`](./design-system.md)의 SVG 5종이 이미 이 방식)
- 세로 영상은 상단 1/3을 인물·제품, 하단 안전영역을 자막에 배정 (storyboard.md와 동일)

### 5-2. 손그림 스타일 — 보조 포맷으로만

Ref 02의 손그림 다이어그램(흰 배경 + 검정 선화 + 빨강/주황/파랑 손글씨)은
"AI 티가 안 난다"는 강점이 있어 유용하다. 다만 **적용 범위를 제한**한다.

| 용도 | 판정 |
|---|---|
| 개념 설명 다이어그램 (결제 흐름, 비교 구조) | ✅ 사용 |
| 여행 동선·지도 안내 | ✅ 사용 |
| 제품 스펙·조건 설명 | ❌ 실캡처 유지 — 손그림은 "대략적"으로 읽혀 정확성 신뢰가 떨어짐 |
| 카드 실물 표현 | ❌ 공식 애셋만 |

### 6-1. 디스클레이머

일본은 2023년 10월부터 경품표시법상 광고에 `#PR` 표기가 **법적 의무**이며 책임은 사업자 측에 있다.
토스 가이드 체크리스트의 "디스클레이머가 눈에 보이는 곳에"와 같은 항목이다.

- 제품·추천코드를 언급하는 모든 포스트에 `#PR`
- 프로필에 대외활동 계정임을 일본어로 명시
- **이미지 안에도 디스클레이머 줄을 넣는다** — 캡션은 접히지만 이미지는 안 접힌다

팀 공식 추천 링크는 아래 하나뿐이다. **다른 링크를 임의로 만들지 않는다.**

```
https://toss.im/?pid=referral_partners_online_FORICREW09
```

배치는 플랫폼마다 다르다.

| 플랫폼 | 배치 |
|---|---|
| Instagram (피드·릴스 캡션) | **캡션 안 링크는 클릭되지 않는다.** 캡션에는 `プロフィールのリンクから` 유도 문구만 넣고, 실제 URL은 프로필 편집 → 웹사이트 칸에 등록 |
| X | 본문에 외부 링크가 있으면 도달이 눌리는 경향 → **본문에는 링크 없이 발행, 발행 직후 첫 리플로 링크를 단다** |
